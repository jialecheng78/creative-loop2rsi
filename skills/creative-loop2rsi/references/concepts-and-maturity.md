# 概念与成熟度

## 1. 先分清四种东西

### Prompt 工程

Prompt 工程修改一次模型调用的任务表达、上下文、示例或输出约束。它可以提升单次结果，但不负责保存状态、追踪证据、恢复失败、判断发布或验证一次修改是否真的更好。

### 反馈 Loop

反馈 Loop 至少包含：

```text
produce → evaluate → decide → revise / commit
```

它的关键不是“多跑几次”，而是每轮都产生可检查的反馈，依据反馈决定继续、提交或停止，并保留前后差异。

### Loop 系统

Loop 系统把一个或多个反馈 Loop 放进共同的运行合同中。它需要状态、证据、预算、停止条件、产物 owner、依赖、恢复和发布门。Prompt 是其中一个可替换部件，Skill 是面向 Codex 的控制面，运行项目才保存具体领域的宪法和历史。

### RSI

本项目把“递归式自我改进”视为更高强度的系统级实验：系统不只改创作产物或创作 Prompt，还能提出修改 Judge、学习策略或改进控制器本身的候选，并由独立证据评价后继系统。

在 v0.1 中，不把以下情况叫作 RSI：

- 同一个 Prompt 重复运行；
- 让模型给自己的文本打分；
- 把多个固定 Loop 串在一起；
- 根据一次失败直接改规则；
- 候选未经 held-out 和人工批准就替换基线。

L5 只提供受限实验形态，不代表完整自主 RSI。

## 2. 脚手架由什么构成

使用四层协作，而不是寻找一条“万能 Prompt”：

| 层 | 负责什么 | 不负责什么 |
|---|---|---|
| Builder Skill | 引导提问、编译合同、选择下一级成熟度 | 保存具体作品和运行历史 |
| 领域 Skill | 表达某一创作方向的方法、术语和交付方式 | 决定系统是否能晋升 |
| 运行控制器 | 校验、封存 attempt、生成候选、晋升、回滚 | 替人判断核心审美 |
| 项目状态与证据 | 保存宪法、配置、run、finding、eval 和 release | 主动执行创作 |

Prompt 工程可以改善 Producer 或 Judge，但只有四层共同存在，才有可恢复、可审计、可验证升级的 Loop 脚手架。

## 3. 成熟度等级

### L0：创作立宪

可运行能力：定义受众、最小成品、必须保留、禁止变化、审美偏好和人的最终决定权。

晋升证据：

- `creative-charter.md` 已覆盖五项 onboarding 输入；
- 受保护项和可探索空间没有冲突；
- 用户明确确认，而非系统自行推断为已确认。

常见假通过：有一份文体 Prompt，却没有最小成品、禁止项或人的决定权。

### L1：单创作 Loop

可运行能力：用一个 `produce → evaluate → decide → revise/commit` Loop 交付完整最小成品，最多重试三次。

晋升证据：

- 至少三条代表任务有完整运行记录；
- 至少两条获得用户认可；
- 失败能定位到当前 Loop；
- 达到预算或连续两次无改善时能够停止。

常见假通过：只保留最终稿，无法解释为何重写或为何停止。

### L2：可靠有状态 Loop

可运行能力：分离 Producer/Judge，封存不可变 attempt，记录 finding 和记忆，支持局部恢复与发布门。

晋升证据：

- 至少五个样本；
- 硬合同没有假 `PASS`；
- 人机 `PASS/BLOCK` 方向一致率默认不低于 80%；
- 至少成功演练一次局部恢复；
- 新 Judge 已经过 shadow 和人工校准。

常见假通过：写了状态文件，但下一轮没有读取；或 Judge 与 Producer 共用候选意图，形成自证。

### L3：嵌套多 Loop 系统

可运行能力：多个 Loop 共享状态和证据，每个产物有唯一 owner，支持局部失效和端到端发布判断。

晋升证据：

- 单 Loop 可重跑且不破坏仍有效的已确认上游；
- 端到端结果不低于 L2 基线；
- 至少解决一个真实观察到的问题；
- 所有循环依赖都有预算和停止条件。

常见假通过：只是把步骤列表改名为多个 Loop，没有 owner、失效传播或局部恢复。

### L4：可验证自我改进系统

可运行能力：从重复 finding 生成隔离候选，修改 Prompt、上下文、Loop 图、记忆或恢复策略，并做目标、回归、held-out 比较。

晋升证据：

- finding 来自至少三次独立真实 run；
- 候选解决目标问题；
- 硬合同无退化；
- 回归没有阻断性退化；
- held-out 不劣于基线；
- 人工批准和回滚点齐全。

常见假通过：一次问题就触发系统改规则，或只在目标样本上变好便替换基线。

### L5：系统级 RSI 实验室

可实验能力：建立修改 Judge、学习策略或改进控制器的候选分支档案，并接受外部元评估。

v0.1 限制：

- 只生成 `CANDIDATE`；
- 不自动晋升；
- 不自动发布；
- 不允许候选修改立宪、held-out、晋升政策或人工边界；
- 必须标记 `experimental / unvalidated`。

常见误称：把 L4 中一次 Prompt 候选晋升称作“系统已经递归进化”。

## 4. 只按证据认定成熟度

区分四种能力标签：

- `implemented`：代码或合同已存在且自动测试通过；
- `forward-tested`：无历史上下文的执行者已在真实形态任务中跑通；
- `proposed`：设计已写明，但没有实现或证据；
- `unvalidated`：实验实现存在，但缺少足够外部验证。

认定当前等级时，取“全部晋升条件都已被证据支持”的最高连续等级。不能跳级，也不能用 L4 的候选文件倒推 L1–L3 已通过。

## 5. 统一对外说法

使用这些表达：

- “已跑通单 Loop”，而不是“已实现自我进化”；
- “当前可证明为 L2”，而不是“配置目标是 L4”；
- “创建了一个 L4 候选”，而不是“系统已经变好”；
- “L5 实验候选，尚未验证”，而不是“完整 RSI”。

每次报告都给出项目内相对证据路径、未满足条件和一项最小下一步。
