# Creative RSI Studio：32,768 打包应用与最小闭环验收报告

## 结论

限定范围内，本轮结论为 **`OPERATIONAL-PASS`**：macOS arm64 的 source-bound 打包应用在固定 `thinking=enabled`、`reasoning_effort=high`、`max_tokens=32,768` 的 Flash epoch 中，完成了真实创作、三项独立作品的重复直接反馈、声明式方法候选、三组人类盲比、明确采用、下一作品实际使用、回滚和退出重启后的状态恢复。

这证明当前打包应用的最小应用级自我改进闭环可以实际运行，但不证明正式 L4、模型权重自改、文学质量普遍提升、V4 Pro、Windows、签名公证或真实非程序员可用性。操作者是 Computer Use simulated-user，不是身份认证过的真人。

## 最小闭环结果

### 1. 三项独立作品与重复反馈

- 独立只读审计确认，当前 observation 绑定三个 distinct `run / work / task receipt / feedback receipt`，三项作品均处于相同模型、参数、Profile、fingerprint 和 baseline method epoch。
- 三份反馈为规范化后完全相同的直接用户反馈；报告不收录反馈原文、作品正文或本地文件路径。
- 保存反馈本身不调用模型；系统只把用户已提交的直接反馈写成本地 receipt 和 finding。

### 2. 候选与三组盲比

- 本轮只有一个通过三组盲比门的成功候选；报告不收录其本地 ID 或存储路径。
- Builder 没有读取 held-out；候选与来源 epoch、三项 source work 和 guidance 哈希均由 Controller 绑定。
- 正常无重试的候选准备使用一次 Builder 请求和四次生成请求：targeted candidate、regression candidate、held-out baseline、held-out candidate。
- targeted、regression、held-out 三组盲比均完整生成，三组决策齐全且候选门通过。
- 报告不公开具体选择、分项 summary、盲比 mapping、作品正文或模型推理内容。

### 3. 采用、下一作品生效与回滚

- 用户明确采用候选后写入不可变 promotion receipt；独立审计确认 registry、proposal 和 receipt 的 method/guidance 绑定一致。
- 采用后另起一项新作品；其 run、task receipt 和 sealed manifest 均精确绑定已采用的 method version 与 guidance 哈希，finding 数量为 `0`。
- 后续显式回滚已恢复 `baseline-v1`，promotion、post-adopt work 和 rollback 历史均保留；应用完整退出并重新启动后，独立只读审计再次确认 active method 仍为 baseline。
- 盲比选择、采用与回滚都是本地治理操作，不调用模型。

### 4. 失败与误操作没有被计入成功证据

验收期间存在一次误提交任务。它被安全收敛为 `CANCELLED`，artifact 和 finding 均为 `0`，没有进入三项 source work、候选、采用或 post-adopt 计数。历史失败报告与失败候选继续保留，没有被本次成功结果覆盖。

## 安全与隐私复核

- fresh preview 的内置最终树审计和独立 manifest exact audit 均为 `PASS`；source renderer exact、无 source map、DSH 包内解析和 sidecar 来源等价性均通过。
- packaged smoke 在未配置 credential 时运行，模型请求为 `0`；真实验收的 API Key、作品正文和模型推理内容没有进入仓库报告。
- 受信 DSH Profile 不挂载会落盘 reasoning 的 Session backend，也不向模型提供 Web、Shell 或动态代码工具。
- DSH Node 子进程仍没有 OS 级强制出网沙箱；受信配置边界不能描述为物理网络隔离。
- 本报告不发布真实 userData、盲比 mapping、Key、日志、候选正文或构建机绝对路径。
