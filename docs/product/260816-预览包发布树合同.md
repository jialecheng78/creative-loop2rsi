# 预览包发布树合同

## 目标

无签名预览包只能包含运行所需字节、许可证与可复核来源证据。构建机的安装状态、本机路径或私有软件源不属于产品运行输入，不得进入 app bundle、Windows unpacked 目录或其 manifest。

## 发布树门禁

- `pnpm deploy` 产物在进入 Electron 包前必须删除 package-manager 的锁文件、工作区配置、安装状态、package map、PnP/integrity 状态和调试日志；运行所需的 `package.json` 不在此列。pnpm workspace/install state 的带版本文件名和 npm/pnpm/yarn debug/error log 也按模式拒绝，不只依赖单个已知文件名。
- 最终发布树必须通过 fail-closed 审计：出现 package-manager 元数据路径、macOS/Linux/Windows 形式的用户 home 绝对路径、package-store 绝对路径，或不在明确公共允许列表内的 registry 配置时，构建立即失败。当次构建机的 exact home（包含文件内恰好以 home 结尾的情况）与 package-store 针对所有 regular-file 原始字节扫描；不依赖已知用户名的通用路径、registry 和 package-store 规则，只对扩展名在允许列表（包含 Python、Shell、PowerShell 与 Windows batch 源文件）、UTF-8 严格可解码且不含 NUL/非文本控制字符的 text-like 文件执行。registry 必须是明确允许 host 的精确 `https` 根 URL，不得使用 bare host 或其他协议，也不得含端口、userinfo、子路径、query 或 fragment；JSON 转义斜杠、Unicode 转义斜杠、YAML inline/block 与 TOML `[registries]` 中的 `default` 写法同样受检查。
- 审计覆盖最终 Electron 发布树，包括 Desktop payload、Controller sidecar、Electron runtime、许可证和来源证据；不能只审计源码树或 deploy 中间目录。
- 所有 symlink 的原始 target 必须是相对路径，必须能 strict 解析，且最终解析位置仍位于发布树内；指向树内的绝对 target 与 broken symlink 也必须拒绝。

## Manifest v2

`StudioPreviewBuildManifest` 与 `ControllerSidecarBuildManifest` 的 `schema_version` 固定为 `"2"`。

排序 inventory 必须包含发布树根目录 `.`、每个目录、regular file 与 symlink。每个条目绑定相对路径、类型和目标平台 mode；此外：

- regular file 绑定字节数与 SHA256；
- symlink 绑定原始相对 target。

macOS 目标的 `mode` 是包含前导零的四位 POSIX 八进制字符串，例如 `"0755"`；Windows 不使用 POSIX 执行位，因此根目录和所有条目的 `mode` 均固定为 `null`。macOS app 主入口与 Controller sidecar 主入口必须是 mode `"0755"` 的 regular file；Windows 则绑定两个 `.exe` 入口的字节和 `mode: null`。

Studio 的 `tree_sha256` 根据排序后的完整 v2 inventory 计算；改变 regular-file 字节、symlink 目标，或任一受治理条目的 POSIX mode 都会改变树哈希。旧 v1 manifest 不能用于新预览包。

## 对用户的影响

界面和创作流程无变化。收口后的预览包不再泄露构建机路径或内部软件源，且可以证明 macOS 主程序与 sidecar 的执行权限未被篡改。

第三方二进制可能保留上游编译机调试路径；这不等于当次构建机泄露。这类文件不跑通用文本 regex，但仍受当次构建机 exact 原始字节针、固定依赖版本、SHA256 和 mode 绑定。
